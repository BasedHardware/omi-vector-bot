# Production answer trace

Draft preparation, October29. Production remains the verified rollback a9c9508/a6ef6b22. This change adds observation only; it does not repair source applicability or authorize a release.

## Boundary and schema

`answerTrace.js` owns one AsyncLocalStorage context per logical support answer attempt. A single `[AnswerTrace]` JSON line is emitted when that attempt settles, including failures, suppressed/no-reply attempts, and the separate pre-work coordination-outage note. Recovered work is a new random attempt, not a customer identity. Non-support commands, private order interactions and webhook notices are outside this observer.

Fields are a random UUID, fixed route/lane and stage outcomes, bounded physical provider attempt outcomes (including compact retry/empty/failed requests), public publisher source metadata, the review results and selected review's first/second-look identity, fixed names of filters which changed text, fixed escalation codes, and confirmed/unconfirmed delivery status. Reviewer source IDs are **model claims**, not independently verified citations. A successful transport with content is not proof of valid JSON or a grounded answer; the separate review fields record acceptance. No prompt, answer, error text, customer/platform/case/order ID, attachment, credential, text length or text fingerprint is stored in this context or emitted by this line.

URL grammar alone cannot establish safe metadata. Existing public ingestion owners enroll URLs from the docs index, Help Center sitemap, successful official repository content and public release API. Request-derived links, model citations, arbitrary source callbacks and stored rows alone cannot enroll a URL. The trace accepts only exact enrolled URLs, with trust derived from the publisher route; Help Center slugs are reduced to the public article number. Unknown or unregistered URLs are omitted and flagged. The registry is a bounded process-local cache of public catalog metadata, not customer state or a new persistent store. Stored-only sources can therefore be omitted after a restart until an existing publisher refresh runs. Other website/feedback/history URLs are currently omitted rather than copied from arbitrary prose. Public catalog origin is not applicability, relevance, a correct source choice or evidence of a released fix.

The line contains no customer correlation ID. Use the platform log timestamp and the random attempt ID to inspect its stages; this deliberately sacrifices direct per-customer search. A confirmed staff send remains confirmed if later case bookkeeping fails. Confirmation means delivery, never acceptance or resolution. Unconfirmed reply sends are recorded as uncertain, not definitely absent; staff `failed` likewise means no confirmed delivery, not proof that nothing arrived. More than one transport attempt may have happened; this is not an exactly-once receipt or outbox replacement. Logger failure is isolated from customer delivery. Existing unrelated log statements are not certified by this change.
